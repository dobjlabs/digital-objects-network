# Bitcraft plugin

`plugin.rhai` and `manifest.toml` are generated by `src/main.rs`. Change
recipes in the generator, never in its outputs. To regenerate, run
`cargo run -p bitcraft-pexe-gen` from this directory (it writes into the
current directory), then `cargo run --release -p pexe -- build examples/bitcraft`
from the repository root, which rewrites the manifest's `module_hash`.

## Naming exception: BucketOfBits

Bucket classes are `BucketOf<Resource>` and their actions
`CraftBucketOf<Resource>`, `BucketOf<Resource>Add<n>` and
`BucketOf<Resource>Take1`, with one exception: the bucket of bits is
`BucketOfBits` (`CraftBucketOfBits`, `BucketOfBitsAdd5`, ...), not
`BucketOfBit`. `bucket_class` in `src/main.rs` is the single place that
decides the name. Everything else that names bucket classes or matches them
by pattern must spell it the same way: the icon rules and `CLASS_ART_FILES`
in `presentation/generate.py`, and the rules, values and class order in
`apps/bitcraft/ui/index.html` and `apps/bitcraft/ui/BITCRAFT_SPECIFIC_RULES.md`.

The presentation pack and the Bitcraft UI have their own rules; see
`presentation/README.md`, `presentation/CLAUDE.md` and
`apps/bitcraft/ui/BITCRAFT_SPECIFIC_RULES.md`.

## Mining is tied to the tool

Every proof-of-work action grinds the mutated tool's `nonce`, after every
other update to the tool, so the tool's new commitment is what the
proof-of-work bounds. A tool's first `nonce` is the grounding block's hash. So
work toward a tool's next use can only start once its previous use is mined,
and a nonce mined for one tool state does not prove for any other: resources
cannot be premined. Mined outputs carry nothing from the grind: a resource
whose key were the tool's nonce could be rekeyed by whoever later holds the
tool. A new tool that mines needs `Tool::mines` to return true, so it carries
a `nonce`.

A caller can supply the tool's new key and nonce as the arguments `<tool>_key` and `grind_nonce`, so that a search run before the action can hash the tool the action will build; `pow_hints.json`, generated with the plugin, names both for each proof-of-work action (see the "Proof-of-work search" section of `apps/bitcraft/README.md`).

A geode records the drill's new commitment as `mined`, written with
`commitment(...)` so the geode holds no copy of the drill's entries, and
cracking compares `mined` against the geode's gem thresholds, so the gem comes
from the mining work itself.
